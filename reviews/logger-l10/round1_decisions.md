# Round 1 decisions (logger L10, live tap)

| # | Severity | Decision | What changed |
| --- | --- | --- | --- |
| 1 | High | Changed | `LiveTap._fail` only records the failure and wakes the tap thread; it cannot raise or write. The tap thread warns once per failure (`_warn`), inside a guard, so a warning filter set to raise cannot reach the caller. Test: `test_warnings_set_to_raise_never_reach_the_caller` (`src/aftershock_logger/live.py`, `tests/test_live.py`). |
| 2 | High | Changed | `read_events` reads both files again when `events.jsonl` was replaced during the reads (compared by device and inode), takes each seq once, and puts a `gap` record wherever seqs after `after_seq` are missing, not only at the start. Tests: `test_a_rotation_between_the_two_reads_hides_no_record`, `test_a_hole_in_the_middle_is_a_gap_record`. |
| 3 | High | Changed | `RunLogger.close` closes the tap before the lock goes and, when the tap thread is still busy after its short wait, hands the lock to the background release thread that already waits for stuck frame writers, so a later writer cannot start until the tap thread has exited. This case raises nothing. Unsaved stopped runs are now spilled before the lock is released too. Test: `test_a_tap_still_writing_at_close_keeps_the_lock_until_it_is_done` (`src/aftershock_logger/logger.py`). |
| 4 | High | Changed | Each accepted frame publishes one new snapshot dict (run id, frame, mode, prompt, subtask, an owned copy of `observation.state`, each camera's time) by one assignment; run fields, REC counts and camera sizes are replaced whole, never changed in place. The status is built from one snapshot. Tests: the real time replay's tight reader now checks that every status's joint state belongs to its frame; `test_the_snapshot_owns_the_joint_state`. |
| 5 | High | Changed | The cleaner also cleans dictionary keys. Camera ids used in status keys and preview file names are the cleaned camera names, made unique. Test: `test_camera_names_with_private_text_are_cleaned_in_keys_and_file_names`. |
| 6 | High | Changed | The test now also times the whole `add_frame` or `put` call in matched real time replays with the tap off and on, and checks that the tap stayed healthy. The short run asserts the hook's thread CPU time (150 samples make a wall clock p99 one lock wait); `AFTERSHOCK_LIVE_BENCH=1` runs 2,000 frames with two 480x640 cameras, asserts the hook's wall clock p99, and prints the whole call figures for the pull request. The whole call p99 is reported, not asserted: in `add_frame` it includes LeRobot's own image writes, whose jitter is larger than the budget with the tap off too. |
| 7 | Medium | Changed | `_write_previews` takes each slot with `pop(cam, None)` and skips a slot a run end removed. Test: `test_ending_a_run_while_a_preview_is_encoded_does_not_stop_the_tap`. |
| 8 | Medium | Changed | The stop is published when the caller is first told of it (`FrameQueue._tell` calls the tap's `stop_seen`, phase `detected`), then again after the quarantine write (`quarantined` or `not_written`), after `run.retry_quarantine()` and after a spill on close (`spilled`). Test: `test_a_controlled_stop_shows_when_it_is_detected_and_again_when_its_frames_are_written` (`src/aftershock_logger/frame_queue.py`, `logger.py`). |
