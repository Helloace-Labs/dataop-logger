# Round 1 decisions: logger LG7 (subtask prompts)

1. **High, subtask label changes leave exports marked current.** Changed. A `task+subtasks` export records `subtask_digest` per run: the sha256 of the run's subtask segments in effect (ids and ranges, `export.subtask_digest`). `training_sets()` counts a run as changed when its review digest or, for a run that recorded one, its subtask digest no longer matches, so a mapping only change (a step's subtask id going from `unresolved` to a real id, with the review digest the same) puts the set out of date. A default export records no subtask digest and is judged exactly as before. New test `test_a_subtask_mapping_change_puts_a_subtask_prompt_set_out_of_date`. Files: `src/aftershock_logger/export.py`, `tests/test_export_prompts.py`.
2. **High, the compatibility test cannot detect changed default bytes.** Changed. `tests/export_baseline.py` builds a fixed fixture (seeded run and batch ids; a teleop run with recorded steps, a segments edit and a cut, a short teleop run, and a policy run with a rescue, a cut and a failure) and exports it with every recipe (teleop, lora, filtered, dagger, residual). `tests/data/export_default_baseline.json` was written by that script from the logger on main, before this change. The new test compares the current default export with it: the report and the record (keys and every field that does not carry a time, an id, a path or a digest of a file with times), and every written episode's prompt, source frames, actions and features. The LeRobot files' own bytes are not in the baseline because LeRobot writes `meta/stats.json` keys in an order that changes with the Python hash seed and between LeRobot versions; the same comparison by tree digest with a fixed hash seed was done once by hand and matched. Files: `tests/export_baseline.py`, `tests/data/export_default_baseline.json`, `tests/test_export_prompts.py`.

## Confirmation round (round1_confirm_codex.md)

Fix 1 was approved. Fix 2 got a new High: the baseline dropped volatile keys instead of masking them, so a key that disappeared from a run record would pass, and the sources were compared by key names only.

- **High, the baseline still misses record regressions.** Changed. `tests/export_baseline.py` now keeps every key and masks only the values of keys that differ between two builds of the fixture (`root`, `review_digest`, `ticks_sha256`, `manifest_sha256`, `at`, `lerobot`); a null stays null, so a value that goes missing shows. The report and the record compare their sources with all other values (batch, batch id, status, lock `by` and `forced`, `lists_sha256`) and the record's version keys. The baseline was written again from the logger on main, twice, with identical bytes, and the current logger's default export gives the same file. Files: `tests/export_baseline.py`, `tests/data/export_default_baseline.json`. Checked by a second confirmation round (`round1_confirm2_codex.md`).

## Second confirmation round (round1_confirm2_codex.md)

- **High, nested source digest keys are still hidden.** Changed. `_mask` now keeps every nested key under a volatile key and masks only the leaf values that are not null, so `sources[].lerobot` is compared as `{data, meta, videos}` with `videos` null. The baseline was written again from the logger on main, twice with identical bytes, and the current logger's default export gives the same file. Files: `tests/export_baseline.py`, `tests/data/export_default_baseline.json`. Checked by `round1_confirm3_codex.md`.
