# Logger L9, round 1 decisions

Codex round 1 (`round1_codex.md`): request changes, 6 High, 2 Medium.

| # | Finding | Decision | Where |
| --- | --- | --- | --- |
| 1 | High: failed-run coverage does not prove the frames survived | Changed in part. `validate` now requires a failed run's record in quarantine: its manifest and ticks, whole by their digests, with the run's length and session range; a missing or damaged record is an error, not a warning. Rejected in part: keeping every observation of a run whose save failed would mean holding a whole episode's images in memory or reading LeRobot's private episode buffer. A failed save means the dataset write failed; the run keeps its range in the session as a failed write (the control loop doc's rule), its sidecar is kept, and the session ends `fault_stop`. The frame queue (L5) remains the path that keeps observations of a stopped run. | `session.py` (`_check_failed_run`), `tests/test_session.py` (`test_failed_run_needs_its_quarantined_record`), SPEC.md |
| 2 | High: closing silently discards the active gap | Changed. `close()` on a session that was not finalized seals an open episode as `system_error` (with a `fault` row `session_closed`) and writes it, saves the active gap and flushes the record and evidence; the session stays open. Errors are raised, or warned when another exception is leaving the block. | `session.py` (`close`, `__exit__`), test `test_close_keeps_an_open_episode_and_the_active_gap` |
| 3 | High: gap finalization failures are hidden | Changed. `finalize` closes and finalizes the gap dataset before it writes the final record; a failure records `persistence_error`, raises, and leaves the session open. | `session.py` (`finalize`, `_close_gap_dataset`), test `test_a_gap_dataset_that_cannot_finalize_fails_the_session` |
| 4 | High: short stop replay changes recorded ticks | Changed. The session keeps only the observations; each tick is moved from the run's own rows (later rewards kept), terminal flags cleared, and the run's events move with their frames. Predictions of a short stop are not kept (documented). | `session.py` (`_replay`), test `test_short_stop_moves_ticks_as_recorded` |
| 5 | High: validation accepts records the cloud rejects | Changed. The go is checked at construction and in `validate` as the cloud takes it (UTC `at`, scope record with its five keys). `validate` checks field types, times, run and gap entries with exactly their keys, reset checks and `stopped`. | `session.py` (`go_problems`, `record_problems`), mutation cases in `test_validate_finds_broken_session_records` |
| 6 | High: gap annotations can disagree silently | Changed. `short_stop`, `moved_by` and `reset_checks` are compared with the gap's sidecar. | `session.py` (`session_problems`), mutation cases |
| 7 | Medium: an index failure mislabels a committed run | Changed. The write status follows the run's state: a committed manifest is `committed`, and a failure after the commit is warned. | `session.py` (`write_pending`), test `test_a_failure_after_the_commit_keeps_the_run_committed` |
| 8 | Medium: the cloud round trip is optional | Rejected. The cloud models live in the private repo and are not published as a package. The round trip is a required test there, at the logger's pinned commit, in the change that moves the pin (acceptance item 3). This repo keeps the optional test for local runs. | none |
