Review: `round1_claude.md` (fallback reviewer, Codex at its usage limit), on commit 69e9286. It counts as full round 1. It approved with no High or Medium findings and three Lows. All three are fixed in this change.

| Finding | Decision | What changed |
| --- | --- | --- |
| L1 viewer take backs were stored under the viewer's label, not `take back` | Changed | `fmt.retract` no longer takes a `what`: its history step is always `take back`, as in the shared format. `review.decide` drops the recorded label for a take back, so the viewer's name for the action ("delete label", "undo cut ...") is still returned to the page for that action but is not stored. SPEC.md (Operations) now says the step's `what` is always `take back` whatever the viewer calls it. Files: `src/aftershock_logger/review_format.py`, `src/aftershock_logger/review.py`, `SPEC.md`. Test: `test_a_take_back_in_the_viewer_is_stored_as_take_back_whatever_the_viewer_calls_it` (fails without the fix: the stored step reads `undo cut 4-9`) |
| L2 two lone surrogate cases were refused for status, not for the text | Changed | `_with_open_proposal` returns the open proposal's id, and the accept and reject cases in `_surrogate_calls` target it. `test_operations_refuse_a_lone_surrogate_even_when_they_change_nothing` now requires the text error for every call, and runs each call again with the surrogate replaced to show it would go through, so the text is the only reason. File: `tests/test_review_format.py` (fails with the old target: accept refuses for status) |
| L3 the payload before id order and the take back field rules were pinned only by tests that need the reference | Changed | (a) New case `replace_refused_for_its_payload` in `tests/review_cases.py`: a replace refused for its payload, then calls that draw ids, a second replace, a refused replace and a take back of the replacement. `expected.json` pins its bytes, so drawing the id before the payload check fails `test_operations_give_the_reference_bytes` without the reference. Besides one random change per path, every take back field of each taken back edit and snapshot is set to every value. `test_random_changes_to_a_review_with_take_backs_are_refused_or_accepted_as_the_reference_did` runs without the reference; disabling the set together, the unknown together, the taken back edit shape or the names nobody rule each fails it. The `take_back` final text was also added to the two reference-live random tests. `_mutations` and `_apply` moved to `review_cases.py` so `make_fixtures.py` can use them. expected.json was regenerated from the reference at Aftershock main d406a25 (after 57b2262); every earlier entry is unchanged |
