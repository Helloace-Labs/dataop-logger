# Round 1 decisions (logger: video encoder backpressure, Aftershock issue #479)

| Finding | Decision | Change |
| --- | --- | --- |
| 1 High: a direct stop can lose the recorded prefix (a prediction for the frame not recorded fails the seal) | Accepted. After an encoder stop, `_seal` leaves out predictions whose frame was not recorded (the stop's message counts them). If the seal still fails, the recorded frames are quarantined like a queued run's (the run keeps low-dimensional frame values in direct mode when the dataset streams video), never discarded. | `src/aftershock_logger/logger.py` (`_seal`, `_save_after_encoder_stop`, `_quarantine_direct`, `add_frame`), `src/aftershock_logger/frame_queue.py` (`observation_values`); tests `test_a_direct_stop_keeps_its_frames_when_a_prediction_names_the_frame_not_recorded`, `test_a_direct_stop_that_cannot_be_sealed_quarantines_every_frame` |
| 2 High: repair can commit a known video mismatch | Accepted. `repair` checks the matched episode's camera counts and quarantines the run with the reason instead of committing it. | `src/aftershock_logger/validate.py` (`repair`); test `test_repair_never_commits_a_run_whose_saved_video_differs` |
| 3 High: Drive gaps can erase the backlog reason | Accepted, for episodes and gaps. The label `encoder_backlog` is now added in `_seal`, so a gap sealed with `unknown` keeps it. The session records a `fault` row (`logger_failed`) at the stop, refuses further frames and new episodes, and ends as `fault_stop` with `logger_failed`. (Today a gap dataset does not stream video, so a gap itself cannot hit the encoder budget; the episode case is the real one.) | `src/aftershock_logger/session.py` (`_encoder_stopped`, `add_frame`, `start_episode`, `finalize`), `src/aftershock_logger/logger.py` (`_seal`); test `test_a_drive_episode_that_hits_the_budget_faults_the_session_and_keeps_its_frames` |
| 4 High: missing camera counts silently pass | Accepted. `adapter.episode_video_frames` gives a count, or None, for every camera whose video is encoded; a camera not encoded yet (batch encoding) is left out. A None is a problem at save (not committed) and in validate. The metadata reads stay in `adapter.py` (`saved_video_frames`). | `src/aftershock_logger/adapter.py`, `src/aftershock_logger/logger.py` (`_save_and_commit`), `src/aftershock_logger/validate.py` (`video_frame_problems`); test `test_a_count_the_episode_record_does_not_give_is_a_problem` |
| 5 High: the backpressure test can pass without backpressure | Accepted. The encoder read now takes 0.3 s, three times LeRobot's own 0.1 s put timeout and well inside the 2 s budget, and the test asserts the logger saw full encoder queues (a spy on `adapter.encoder_full`) as well as every frame in the decoded video. | `tests/test_encoder_backpressure.py` (`test_a_slow_encoder_gets_backpressure_and_loses_no_frame`) |
