# Round 1 decisions: logger import presets

1. **High, transition columns invent success labels.** Changed. Auto-detect picks `lerobot-hil-record` only when HIL-SERL's `complementary_info.discrete_penalty` column is there next to `next.reward` and `next.done`. A dataset with `next.reward` or `next.done` and no such marker now gets `plain`, which maps nothing, so no outcome is claimed (it got `demos` before this change, which claimed success). The HIL presets keep reading success from `next.reward` when chosen, since that is how HIL-SERL marks success. New test: a failed episode with dense positive rewards imports as `plain` with an unknown outcome. Files: `src/aftershock_logger/importer.py` (`detect`, docstring), `README.md`, `tests/test_import_presets.py`.
2. **High, invalid rewards produce confident outcomes.** Changed. A threshold outcome is decided by finite values only: success when a finite value is above the threshold, failure only when every value is finite, otherwise unknown with a note that names the count of missing or non-finite frames. New parametrized test covers NaN, all NaN, infinity, NaN with a finite success, and all zero. File: `src/aftershock_logger/importer.py` (`_build_run`), `tests/test_import_presets.py`.
3. **Low, design table keeps the old outcome rule.** Changed. The field mapping table now describes a custom `next.success` column as true on any frame and the HIL presets' `next.reward` threshold. File: `docs/DESIGN_batches_import_export.md`.
