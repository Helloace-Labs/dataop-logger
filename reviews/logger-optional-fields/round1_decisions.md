# Round 1 decisions: logger-optional-fields

Codex verdict: request changes, 5 High and 3 Medium.

| # | Severity | Finding | Decision | Files |
| --- | --- | --- | --- | --- |
| 1 | High | A run started without a policy wrote `policy: null`, which now reads as "no policy ran" even when the policy drove | Accepted. `log.run(policy=...)` defaults to `"unknown"`. `policy=None` means no policy ran, and `add_frame` then refuses a `base_action` or a `base` or `blend` frame before LeRobot sees it. Any other policy value is refused | `src/aftershock_logger/logger.py`, `tests/test_planned_fields.py` |
| 2 | High | Unknown counters are stored and read as -1, while the schema's record form is the literal `unknown` | Changed. A parquet int64 column cannot hold the string, so -1 stays the on-disk form (as for `inference_id`), and the training reader keeps -1 for its tensors. New `reader.tick_records(run_path)` returns each tick in the schema's record form with the literal `unknown` for unknown counters and for every L2 field of an older run. Tests cover both; the records from this branch validate with the Aftershock contract models (checked outside this repo) | `src/aftershock_logger/reader.py`, `SPEC.md`, `tests/test_planned_fields.py` |
| 3 | High | With `planner=None`, an omitted `subtask_cmd` became null, a guess | Accepted. An omitted `subtask_cmd` is always `unknown`; null only when the caller passes `None` | `src/aftershock_logger/logger.py`, `tests/test_planned_fields.py` |
| 4 | High | A constant expert mapping on import set policy, planner and `subtask_cmd` to null, although a scripted skill may run with a planner or a shadow policy | Accepted. Null policy or planner now needs `"policy": null` or `"planner": null` in the mapping; the `demos` preset declares both. `subtask_cmd` is always `unknown` on import. A mapping that says no policy ran while the policy drove frames skips the episode with the reason. A mapping can give the planner as `{name, id}`; `origin.fields` records where policy and planner came from | `src/aftershock_logger/importer.py`, `tests/test_planned_fields.py` |
| 5 | High | With `planner=None`, a changing prompt passed, though it means a planner is present | Accepted. With planner null, a known prompt that differs from the previous known prompt is refused by `add_frame` and reported by `validate` | `src/aftershock_logger/schema.py`, `tests/test_planned_fields.py` |
| 6 | Medium | The viewer called `.get()` on a `"unknown"` policy and crashed | Accepted. The viewer treats null and `unknown` policies as no record. Test lists an unmapped import and a demos import | `src/aftershock_logger/viewer.py`, `tests/test_planned_fields.py` |
| 7 | Medium | An empty prompt was refused, though the contract accepts any string | Accepted. Any string is a prompt; only null is refused by `validate`. Test round trips an empty prompt | `src/aftershock_logger/schema.py`, `src/aftershock_logger/validate.py`, `tests/test_planned_fields.py` |
| 8 | Medium | Contract model validation and the 40-run recorded fixture are not in the tests | Rejected for this repo. The contract models and the recorded fixture are not public and cannot be imported or read by this public repo's tests. Both were checked by hand on this branch: manifests and tick records from live runs (every field, defaults, no planner) and from plain and demos imports validate with the contract models, and a copy of the 40-run fixture validates (40 runs, 31 success, 9 failure) with its manifests and tick records accepted by those models. The Aftershock repo's own CI runs the fixture tests against the pinned logger | none |

Tests: 200 passed (136 before this change).
