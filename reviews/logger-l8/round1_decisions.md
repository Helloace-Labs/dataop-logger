# Round 1 decisions (logger L8)

Review: `round1_claude.md` (fallback reviewer, Codex at its usage limit), on commit 722e94e. It counts as full round 1. One High, four Medium and three Low findings. Questions about the shared format itself (a take back operation, segments without a task, lone surrogates, the uuid check, the wording on `agent_version`) go to a separate Aftershock contracts issue, opened by the lead. This change does not depend on their answers.

| Finding | Decision | What changed |
| --- | --- | --- |
| H1 named segments shown under a derived id, losing step status and reason | Changed | The logger no longer derives subtask ids from names. A segment a person or agent names is stored as `unresolved` with the name kept in `legacy_name`, the same way the migration stores a name that matched nothing, so nothing is invented. `effective()` names it by that name, so matching against the recorded steps keeps their status and reason. In a review migrated from format 1, a name the `legacy_subtask_map` already has keeps the id the map gives it, and a new name is added to the map as `unresolved`, because the format requires every named segment to agree with the map. `subtask_id_for` and the id matching in `lists.py` and `viewer.js` are removed. Files: `src/aftershock_logger/review.py` (`_input`, `_segment_names`, `_propose`, `replace_edit`), `lists.py` (back to main), `viewer.js`, `SPEC.md`. Tests: `test_named_segments_keep_their_names_status_and_reason_and_get_no_invented_id` (mixed case, several words, a non-Latin name, over a recorded failed step) and `test_named_segments_in_a_migrated_review_keep_its_map` (with and without a task) |
| M1 id collisions, Python and JS deriving ids differently, and saving a plan giving ids to migrated unresolved segments | Changed (follows from H1) | No ids are derived, so the collisions and the Python and JS difference are gone, and non-Latin names keep their names. A migrated `unresolved` segment that the viewer sends back by name stays `unresolved` with its name (covered by the migrated map test) |
| M2 `retract` overwrites who accepted the edit | Changed | `retract` keeps the acceptance's `decided_at` and `decided_by`, and only sets the status to `rejected` (with its `accepted_seq`, as format 1 recorded a take back). The take back is recorded in its own history step, whose `at` says when and whose `what` names who took it back. File: `src/aftershock_logger/review_format.py`. Test: `test_logger_only_operations_write_ordinary_format2_reviews`. Whether the shared operations should have a take back operation goes to the contracts issue |
| M3 test gaps | Changed | Real files: the test now checks that each file's batch lock digest (`batches.review_digest`, a digest of `effective()`) is the same as the one the format 1 logger gives. That logger is read from this repo's history at the last commit before this change. The digest also stays the same after the file is rewritten as format 2. The same comparison runs on the synthetic fixtures without needing real data (`test_effective_matches_the_format1_logger_from_history`). Reference implementation: `propose_many`, `decide_many` and `retract` results, including a take back of a label that has a reading, load in the reference reader with the same bytes. The shared operations (undo across a take back, accept, replace, sign off) then continue the same way on both sides (`test_logger_only_steps_load_in_the_reference_and_its_operations_continue_after_them`). The H1 cases are added |
| M4 lone surrogates | Changed | Checked against the reference reader. It refuses a lone surrogate in any text field that has a limit (a length, not blank or a pattern) and accepts one in the three unlimited ones (`by`, `reason` and a step's `what`). `_str` now refuses them in the same fields. Lone surrogates were added to the random changes, and `test_lone_surrogates_are_refused_or_accepted_like_the_reference` sets every text field of three reviews to three surrogate values and requires the same answer as the reference |
| L1 `agent_version: unknown` on new proposals, and duplicate proposals when an agent runs again | Changed | New agent proposals record the caller's `--agent-version`, or the logger's own version when none is given (never `unknown`). `interpret`, `annotate`, `note` and `suggest-cut` take `--job-id` and `--agent-version`. `annotate` uses one job id for the whole call. (Repeats: see N1 below.) Test: `test_agent_values_name_a_version_and_a_rerun_adds_nothing` |
| L2 `migrate-reviews` exits 1 on locked batches | Changed | Runs in a locked batch are reported as skipped (their files are read through the migration until the batch is unlocked), and only real refusals exit 1. Test: `test_migrate_reviews_skips_locked_batches` |
| L3 proposals list shows raw ids | Changed | The "Proposed by agents" list shows a segment by its name (`legacy_name`) through the dataset's list name |

Tests: 264 passed and 1 skipped on main before the change. Now 302 passed and 56 skipped without the optional inputs, and 357 passed and 1 skipped with the reference implementation and the real data folder set. The originals of the real files were only read; their checksums are unchanged.

## Confirmation round 1

Review: `round1_confirm_claude.md` (fallback reviewer), on commit 41766bb. All eight round 1 fixes were confirmed. It found one new Medium and two follow ups.

| Finding | Decision | What changed |
| --- | --- | --- |
| N1 the L1 fix returned an open proposal from the same agent whatever its job or version, so a new job or a newer agent version was swallowed | Changed | The logger-only repeat check is removed. Repeats are decided only by the format's own rule in `propose`: the same source, by, job_id, agent_version and value while the proposal is open. An agent that runs again and wants no repeats passes the same `--job-id` (and version). Files: `src/aftershock_logger/review.py`, `annotate.py`, `cli.py`. Test: `test_agent_values_name_a_version_and_a_rerun_adds_nothing` now checks that the same job adds nothing and that a new job or a new version each get their own proposal |
| N2 `migrate-reviews` reported any batch error as a locked batch | Changed | Only a run whose batch has status `locked` is reported as "skipped, batch locked". An unreadable or malformed batch file counts as a refusal, with its reason, and the command exits 1. File: `src/aftershock_logger/cli.py`. Test: `test_migrate_reviews_skips_locked_batches` covers both |
| N3 after a take back, the edit reads as rejected by the person who accepted it once the history step is dropped | No code change | Part of the take back recording question for the shared format, Aftershock contracts issue #81 |

Tests: 302 passed and 56 skipped; with the reference implementation and the real data folder, 357 passed and 1 skipped.
